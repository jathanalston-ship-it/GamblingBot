# add-migration — safe Alembic migrations

Migrations here are numbered `0001…NNNN` and must leave `alembic check` clean.

## Steps

1. **Register the model** so Alembic can see it: import it in
   `src/momentum/persistence/models/__init__.py` and add it to `__all__`.
2. **Autogenerate against a temp DB** (so you don't touch `data/momentum.db`):

   ```bash
   tmp=$(mktemp -u --suffix=.db); export DATABASE_URL="sqlite:///$tmp"
   PYTHONPATH=src alembic upgrade head
   PYTHONPATH=src alembic revision --autogenerate -m "add <thing>"
   ```

3. **Renumber** the generated file to the next `NNNN_<name>.py`, set
   `revision = "NNNN"` and `down_revision = "<previous NNNN>"`, drop the
   autogenerate comment lines, and format it like the existing migrations.
   Use `batch_alter_table` for index/column changes (SQLite emulates ALTER by
   table-rebuild and needs named constraints — the project's naming convention
   handles this).
4. **Verify drift + round-trip:**

   ```bash
   rm -f "$tmp"; PYTHONPATH=src alembic upgrade head
   PYTHONPATH=src alembic check                 # expect: No new upgrade operations detected
   PYTHONPATH=src alembic downgrade -1 && PYTHONPATH=src alembic upgrade head
   rm -f "$tmp"
   ```

5. Delete the temp DB and the autogenerated (pre-renumber) file if any.

## Conventions

- `created_at`/`updated_at` use `server_default=sa.text("(CURRENT_TIMESTAMP)")`.
- Index/PK/UQ/FK names come from the metadata naming convention in
  `persistence/models/base.py` — let Alembic emit `op.f(...)` for them.
- Add an `__table_args__` composite index for the common query path; keep
  migrations and models in lockstep (the `make check` gate runs `alembic check`).
