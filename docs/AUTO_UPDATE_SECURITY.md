# Auto-Update — Security Review

Security audit of the in-app auto-update (electron-updater) for **public-repository
deployment**. Companion to `docs/AUTO_UPDATE_AUDIT.md` (which diagnosed the
`releases.atom` 404 = repo is private). **Verdict: ✅ the update mechanism exposes
no secret, uses no credentialed URL, requires no token, and works against public
GitHub Releases.** The only remaining step is a repository setting (make it public).

## Current configuration

| Item | Value | Source |
|---|---|---|
| Provider | `github` | `desktop/electron-builder.yml` → `publish:` |
| Owner / repo | `jathanalston-ship-it` / `GamblingBot` | same (baked into `app-update.yml`) |
| Feed URL (read by electron-updater) | `https://github.com/jathanalston-ship-it/GamblingBot/releases.atom` | `GitHubProvider` (unauthenticated) |
| Download URLs | `https://github.com/.../releases/download/v<x>/MomentumLab-Setup-<x>.exe` | release assets |
| Release metadata | `latest.yml` (version + SHA-512 hashes), `*.blockmap` | electron-builder, uploaded by the release workflow |
| Token | **none baked in.** Optional, env-only: `MRP_UPDATE_TOKEN` → `GH_TOKEN` → `GITHUB_TOKEN` | `main.ts updateToken()` |
| Auth transport (if a token is set) | `autoUpdater.requestHeaders = { authorization: "token …" }` — an HTTP **header**, never the URL | `main.ts initAutoUpdates()` |

`app-update.yml` (generated by electron-builder, shipped in the package) contains
**only** `provider`, `owner`, `repo`, `updaterCacheDirName` — no secret.

## Required configuration (public deployment)

| Setting | Required value |
|---|---|
| Repository visibility | **public** (so the anonymous `releases.atom` feed returns 200) |
| `publish.provider/owner/repo` | as above — already correct, **no change** |
| Release assets per release | `latest.yml` + `MomentumLab-Setup-<v>.exe` + `*.blockmap` — already published |
| Token | **none.** Do **not** set `MRP_UPDATE_TOKEN` for a public repo; do **not** embed any token in the build |

Nothing else is needed. A token is required **only** if you choose to keep the repo
private (internal distribution) — and even then it is read from the environment,
never embedded.

## Security review (the four requirements)

### 1. The update feed cannot expose secrets ✅
- `app-update.yml` carries only provider/owner/repo (no credential).
- `latest.yml` carries only the version, file paths, sizes and SHA-512 hashes — no
  secret. (`--publish never` in CI means electron-builder never writes a token into
  any artifact; the workflow uploads the files itself.)
- The feed is **read-only public metadata**; there is no field in which a secret
  could appear.

### 2. Update URLs contain no credentials ✅
- The feed URL is `https://github.com/<owner>/<repo>/releases.atom` and download
  URLs are `https://github.com/.../releases/download/...` — plain HTTPS, **no
  `user:pass@`, no `?token=`**.
- When a token is configured (private-repo option) it is sent as an
  `authorization` **header**, never placed in a URL.
- Verified: `grep` of the compiled `dist-electron/main.js` + `preload.js` for
  `//user:pass@`, `releases.atom?`, `token=` → **no matches**.

### 3. Updater tokens are not required ✅
- `updateToken()` returns `null` when no env var is set; `requestHeaders` is only
  assigned when a token is present. For a public repo the anonymous feed returns
  200, so **no token is required**.
- No token is baked into `electron-builder.yml`, `app-update.yml`, `package.json`
  or the build — the token is **env-only** and optional.

### 4. Updater works against public GitHub Releases ✅
- Verified live: a public repo's feed
  (`https://github.com/electron/electron/releases.atom`) returns **HTTP 200**
  anonymously, exactly what electron-updater needs.
- Our releases already carry the required assets (`latest.yml` + installer +
  blockmap, verified via the GitHub API). So the moment the repo is public, the
  updater resolves the feed and updates with **no token**.

### Secrets never reach the renderer ✅
- The Updates screen receives **diagnostics with `tokenConfigured: boolean`** only —
  never the token value. `updateDiagnostics()` returns booleans/paths/status codes.
- The compiled preload contains **0** references to `MRP_UPDATE_TOKEN` / `GH_TOKEN`
  / `GITHUB_TOKEN`, enforced by `desktop/scripts/no-secret-exposure.test.cjs`.
- The DB URL in the public `release-validation.json` artifact is credential-redacted
  (`redactUrl`, see `docs/WORKFLOW_SECURITY_AUDIT.md`).

|---|---|---|
| `releases.atom` (anonymous) | **HTTP 404** | **HTTP 200** (verified against a public repo) |
| Token required | no | no |
| Secret in feed / URL | none | none |
| Updater functional | no (feed 404) | **yes** (assets already in place) |

**Action required (repository setting, not code):** make
`jathanalston-ship-it/GamblingBot` **public** (Settings → General → Change

## Conclusion

The auto-update system is **safe for public deployment**: no secret can leak through
the feed, URLs carry no credentials, no token is required for a public repo, and it
works against public GitHub Releases. The single outstanding item is flipping the
repository to public.
